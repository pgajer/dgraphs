Use a finite numeric matrix with observations in rows. This example samples a circle, constructs a symmetric nearest-neighbor graph, requests connectivity repair, and measures distances on the final graph.

Use create.graph(type, ...) when you want a familiar topology or a small example. The required type selects the graph; arguments following n must be named. Every result uses the same graph accessors as a data-derived graph.

For chains, span counts positions on each side, so an interior vertex has at most 2 * span neighbors. This differs from k in nearest-neighbor workflows. Optional x sorts vertices by coordinate, with ties resolved by input position; y and labels follow the same ordering. The sorted-to-input mapping is metadata$order. An ordinary star has all arm counts equal to one; larger counts subdivide its arms.

A cycle describes topology. A circle also records unit-circle coordinates in metadata$coordinates and angles in metadata$angles. Circle sampling is "random" by default; "uniform" spaces angles equally. Choose edge.length = "chord" for Euclidean edge lengths or "arc" for shorter circular arcs. A shorter arc can cross an unsampled gap; graph shortest paths still follow the edges actually present. Arc lengths are measured in radians on the unit circle, not squared distances or conductances.

Random graphs have floor(n * mean.degree / 2) edges. A connected graph needs at least n - 1, and an impossible request errors. With connected = TRUE, a growing random tree precedes additional edges; the result is not a uniform draw from all connected graphs. With connected = FALSE, edges are sampled uniformly without replacement from all vertex pairs. Candidate storage is quadratic in the number of vertices, so this generator is intended for small examples. For both random graphs and randomly sampled circles, an explicit seed restores the caller’s random state after generation; seed = NULL uses and advances the current stream. Uniform circle sampling uses no random numbers. Unknown or irrelevant arguments error instead of being ignored.

Conventions that affect your choice

A common graph object

Every graph constructor returns a dgraph, including basic fixtures. Use graph.adjacency(graph) for its neighbor lists, graph.lengths(graph) for aligned lengths, and graph.edges(graph) for one row per undirected edge. graph.order(graph) includes isolated vertices. A bare adj.list has one integer vector per vertex, containing 1-based neighbor indices; length.list gives the corresponding finite, nonnegative lengths.

For one transition release, graph$adj_list and graph$weight_list remain available without warnings. They match the final-stage adjacency and lengths, including vertex labels; weight_list is NULL when no lengths are stored. Treat these fields as read-only snapshots and use the accessors in new code. Native constructor results also retain edge_matrix for this release; new code should use graph.edges(graph).

dgraph(adj.list, length.list) validates reciprocal edges and values, rejects duplicates and self-loops, and sorts neighbors and values together. Omit length.list for topology alone. A stored zero-length edge remains an edge. as_igraph(graph) preserves isolates, lengths as the length attribute, and other named edge attributes. For igraph distance calculations, explicitly use weights = igraph::E(ig)$length. Raw-list matrix conversions retain weight.list for quantities that need not represent distances.

Path-search results contain their graph in $graph and paths in $shortest.paths; a parameter sequence contains separate graph objects. Subgraphs use compact indices and record metadata$original.vertices. create.graph(type, ..., labels = ...) assigns vertex labels independently of adjacency indices. For example, labels = 101:110 names ten vertices without changing their internal indices 1:10.

Neighborhood sizes and edge quantities

All sequence constructors take an explicit, strictly increasing k.values vector with 1 <= k < n. In coordinate and graph-geodesic intersection workflows, k counts other vertices. Each cover explicitly includes its source plus those neighbors. Equal distances are resolved by vertex index, including coincident observations. Coordinate ANN search uses an exact fallback when its boundary candidates are tied. The specialized knn.metric = "linf.simplex" search currently evaluates all candidates to honor the same tie rule, with quadratic distance-evaluation cost. It shares linf.simplex.distances()’s general shortest-path solver, including paths through intermediate faces. Legacy endpoint-face simplex caches are rejected and must be rebuilt; Euclidean caches remain compatible. Search uses row-wise working memory rather than storing an all-pairs distance matrix.

A length-based operation rejects a graph with no lengths; graph.geodesic.distances(graph, distance = "hop") explicitly requests unweighted distance. graph.spectrum(graph) uses the unweighted Laplacian. graph.embedding(graph) is unweighted by default; choose an edge.attribute and transform = "identity" or "reciprocal" explicitly. Layout values must be strictly positive, so zero lengths require a separate, explicit choice of layout quantity.

Connectivity, stages and cost

Mutual, symmetric and radius constructors can leave components separate. Request connect.components = TRUE when bridges are appropriate. Exact component-MST repair joins components through shortest Euclidean bridges; the ANN candidate version can fall back to exact search. A global minimum spanning tree is another repair option. join.graphs() identifies one vertex from each of two graphs and preserves aligned lengths and attributes.

graph.stages(graph) lists the stored stages. Every graph has final; constructors may additionally retain raw, pruned, raw.repaired, pruned.repaired and repaired.pruned. Pass the same stage to any accessor, as_igraph() or graph.geodesic.distances(). A missing stage errors, and stage selection never prunes, repairs or reconstructs a graph. The geodesic intersection constructor stores only final because it performs no pruning or repair. Symmetric kNN’s graph.detail = "minimal" requires both disabled.

Disconnected pairs have infinite distances. All-pairs distances require a quadratic-size matrix; request selected vertices when possible. Geometric pruning and exact component bridging can be expensive even with ANN neighbor search. Native construction is serial; thread controls do not promise native parallel execution.

Distances and stored routes

Use graph.geodesic.distances() for a matrix of distances. Supply exactly one of an existing graph or a coordinate matrix points. With coordinates, graph.type = "sknn" requires an explicit k and builds a symmetric kNN graph without pruning or connectivity repair. graph.type = "mst" builds a Euclidean minimum spanning tree and does not accept k. Setting k = 1 never changes the construction method. Coincident observations remain connected by zero-length edges when selected by the construction.

line.points <- matrix(c(0, 0, 1, 10, 11), ncol = 1)
D.tree <- graph.geodesic.distances(points = line.points, graph.type = "mst")
D.neighbors <- graph.geodesic.distances(points = line.points,
                                       graph.type = "sknn", k = 1)

  pair = c("Coincident observations", "First to last observation"),

  symmetric.neighbor.distance = c(D.neighbors[1, 2], D.neighbors[1, 5])

Both calculations are exact shortest-path distances on their chosen graphs. Neither construction guarantees exact continuous manifold geodesics. The symmetric-neighbor example has disconnected components, represented by Inf. vertices selects matrix rows and columns in the requested order; paths may still pass through any vertex in the graph. distance = "hop" counts edges; distance = "length" requires stored lengths. To reuse a graph or choose additional construction options, construct it first and pass graph = g.

These all-pairs route collections can require substantial memory; use modest hop limits when possible.

For a path expressed as coordinates, path.length() sums Euclidean segment lengths and subdivide.path() includes both endpoints at equally spaced distances along the polyline. Points on opposite sides of a corner need not have equal straight-line distances from each other.

polyline <- rbind(c(0, 0), c(1, 0), c(1, 2))

#> [1] 3
subdivide.path(polyline, n.subdivision.pts = 5)
#>      [,1] [,2]
#> [1,] 0.00 0.00
#> [2,] 0.75 0.00
#> [3,] 1.00 0.50

The five subdivision rows correspond to arc distances 0, 0.75, 1.5, 2.25 and 3. Repeated consecutive points contribute zero length. For a singleton or a path whose points all coincide, length and normalized cumulative distances are zero, and subdivision repeats that location. Empty paths are rejected; subdivision requires at least two output points.

Positive spectra and spectral coordinates

graph.spectrum() uses the final graph’s unweighted combinatorial Laplacian, regardless of stored lengths. Its nev counts positive eigenpairs, ordered from smallest upward. Every connected component, including an isolated vertex, contributes one omitted zero mode. The spectrum records this count as nullity and preserves component IDs in vertex order. nev = NULL requests all positive modes; use a small explicit count for large graphs. Requests larger than the number of positive modes error rather than silently changing the count.

chain <- create.graph("chain", n = 8)
spectrum <- graph.spectrum(chain, nev = 3)
round(spectrum$evalues, 6)
#> [1] 0.152241 0.585786 1.234633
spectrum$nullity
#> [1] 1
coordinates <- graph.spectral.embedding(spectrum, dim = 2)
dim(coordinates)
#> [1] 8 2

The three eigenvalues are approximately 0.152241, 0.585786 and 1.234633; the embedding uses the first two. use.R = TRUE has the same output contract. Both backends honor return.Laplacian = TRUE and return.dense; sparse output uses the optional Matrix package. The native backend uses a sparse solver for partial spectra and a dense solver for the full spectrum. The R backend uses a full dense solve, so both an R solve and a full native spectrum require quadratic memory. A documented absolute tolerance separates computed zero modes from positive modes; an unresolved separation errors explicitly.

Pass the spectrum object to graph.spectral.embedding(). Its default scale = "none" uses orthonormal eigenvectors; scale = "inverse.sqrt" scales each column by the inverse square root of its eigenvalue. With every positive mode on a connected graph, squared distances in the latter embedding equal effective resistance. With fewer modes it is a truncated representation. Neither coordinate choice generally reproduces graph shortest-path distances. Signs and bases in repeated eigenspaces can differ between solvers. Include the whole tied eigenspace when comparing distances between embeddings.

Disconnected graphs have spectra, but no common embedding is assigned: select a component with create.subgraph(graph, which(spectrum$components == id)), compute its spectrum and embed it separately. Distances between independently embedded components have no defined meaning. Empty and singleton graphs have no positive-dimensional spectral embedding.

Plotting a graph and reusing its layout

graph.embedding() computes coordinates without drawing. The standard plot() method for a dgraph computes a two-dimensional layout only when coordinates are absent and invisibly returns the coordinates actually drawn. Use vertex.values for numeric values mapped through a palette, or vertex.colors for explicit colors; supplying both errors. Constant numeric values use the palette midpoint. Every undirected edge is drawn once.

cycle <- create.graph("cycle", n = 8)
set.seed(4101)
xy <- plot(cycle, vertex.values = seq_len(8), main = "Numeric vertex values")

plot(cycle, coordinates = xy, vertex.values = rep(7, 8),
     main = "Same layout, constant values")

The same stage controls both layout computation and drawn edges. For three-dimensional coordinates, choose an explicit two-column projection; the plotting method never silently discards a coordinate. Layout generation itself remains available in both two and three dimensions.

set.seed(4102)
xyz <- graph.embedding(cycle, dim = 3)
colnames(xyz) <- c("x", "y", "z")
plot(cycle, coordinates = xyz, projection = c(1, 3), vertex.colors = "navy",
     main = "Explicit x/z projection")

Reuse an expensive computation

Keep a constructed graph for repeated graph.geodesic.distances() calls; this reuses its edges, not a memoized distance matrix. Save D yourself when reusing the same distances. Coordinate input constructs a fresh graph for each distance call. Geodesic intersection and iterated intersection workflows deliberately build on existing graph metrics.

create.sknn.graphs() reuses one ANN search across its k values. A single symmetric constructor also accepts ordered, 1-based, non-self knn.index rows with neighbor.method = "ann"; these must correspond to the same input points. Intersection constructors expose knn.cache.path and knn.cache.mode: "read" requires a valid cache, "write" replaces it, and "readwrite" creates a missing cache but rejects an existing invalid one. Format version 3 caches store only non-self neighbors and check point values, row order, metric, working-coordinate preprocessing and maximum k. Old cache formats are rejected. The adaptive-radius sequence has a batched ANN backend. These are distinct contracts; there is no universal public neighbor-cache object shared by all constructors. Internal cache and native solver helpers are not installed public functions to call directly.

Edge lengths and connectivity repair always use X. Only observation input with neighbor.method = “ann” supports this argument.

Details

With input.type = “distances”, supplied distances determine exact neighbor rankings, every edge length, and component/global MST repair. Distance input must be finite, nonnegative, square and symmetric, with a zero diagonal. Symmetry and diagonal tolerance is 1e-12 * max(1, max(X)); accepted asymmetry is averaged and the diagonal set to zero. Row and column names, if present, must be identical and unique. Off-diagonal zeros are allowed. Triangle inequality is not tested, so symmetric dissimilarities are accepted. Ties are resolved by increasing vertex index, excluding self explicitly. ANN search/repair and pruning are unsupported for distance input and error. The series constructor validates distances and ranks neighbors once, through its largest requested k. Full lifecycle stages use these same distances.

With no nearest-neighbor ties, the sKNN edge rule is equivalent to

d_{ij} (_i, _j),

where _i is the distance from point i to its k-th non-self nearest neighbor.

If connect.components = TRUE, the graph is augmented with MST edges. The default connect.method = “component.mst” first collapses each connected component of the sKNN graph to one component vertex, weights each component pair by the shortest data-space edge between them, and adds the minimum spanning tree of this component graph. This adds exactly m - 1 bridge edges when the original sKNN graph has m connected components. connect.method = “component.mst.ann” uses ANN nearest-neighbor bridge candidates first and automatically falls back to exact component MST when the sparse candidate graph does not connect all components. With observation input and ANN neighbor search, exact component repair streams distances through Prim’s algorithm without a full distance matrix; worst-case distance work is still quadratic. This does not apply to global.mst, pruning, or the exact neighbor backend, which may allocate dense distances. The alternative connect.method = “global.mst” unions the sKNN graph with the full Euclidean MST on the data points.

neighbor.method = “exact” computes all pairwise distances and is the deterministic reference implementation. neighbor.method = “ann” uses the bundled ANN kd-tree for the Euclidean kNN search step; exact parity can differ only in nearest-neighbor tie cases. Edge weights are always returned as ordinary Euclidean distances. Exact component.mst repair uses exact pairwise bridge distances; component.mst.ann uses ANN bridge candidates before guaranteed exact fallback.

If prune.method = “local.geodesic” or prune.edges = TRUE, an experimental local-geodesic pruning stage is applied after the sKNN support is built and before optional MST connectivity repair. Candidate edges are processed longest-first. For an edge ⁠(i, j)⁠, the edge is removed only when the currently retained graph contains an alternative path from i to j, restricted to the union of their local neighborhoods, whose length is at most prune.tau times the direct edge length. prune.method = “global.geodesic.ratio” instead uses the whole graph as the alternative-path search domain and removes long edges whose shortest alternative path is within the configured geodesic-ratio threshold.

Value

A dgraph object. Use graph.adjacency(), graph.lengths(), graph.edges() and graph.stages() to inspect its stored graph stages. Construction and diagnostic information is stored in metadata.

Details

Groisman, Jonckheere and Sapienza define the unrooted complete-graph estimator and prove consistency after sample-size normalization under their sampling assumptions. Their Proposition 2.12 establishes a high-probability equality for a sufficiently large nearest-neighbor restriction under its stated assumptions. It does not certify arbitrary fixed k, pruned graphs, or arbitrary supplied lengths. This function applies neither sample-size normalization nor an estimated limit constant.

Both coordinate constructions evaluate all Euclidean pairs. Explicit complete graphs store quadratic adjacency. Overflow, positive powered lengths underflowing to zero, and a conservative upper bound on simple-path cost exceeding the numeric range cause errors; rescale base lengths before retrying. Multiplying lengths by a > 0 multiplies unrooted distances by a^p (rooted distances by a).

With return.graph = TRUE, one deterministic shortest-path tree is selected per source (ties need not include every minimizing path). Only paths to the requested targets contribute edges. The returned graph retains all input vertices, including unused isolated vertices. Its edge lengths are powered base lengths even when the returned distances are rooted. Thus graph geodesics reproduce the unrooted requested distances. With all sources and targets it preserves every pair; a subset guarantees only the requested pairs. The union need not be sparse. The implicit workspace estimate includes a conservative allowance for the predecessor-edge union when requested.

Exact Euclidean search algorithm passed to FNN::get.knnx(): “kd_tree” (default) or “brute”.

Details

The unrooted distance is the minimum sum of Euclidean edge lengths raised to p, allowing paths through all observations. Rooting preserves neighbor rankings. Lemma 5.6 of McKenzie and Damelin justifies pruning to directed Euclidean neighbor lists for nearest-neighbor queries. This does not establish equality of all pairwise distances on the sparse graph. The paper counts the source among its neighbors; here k excludes it.

Equal-distance neighbors at the cutoff may be selected arbitrarily; their identities need not agree across search algorithms or permutations. Duplicate observations are retained as distinct vertices with zero distance. Exactness refers to the complete-graph target, subject to floating-point arithmetic. Extremely disparate coordinate scales should be rescaled. Nonfinite computed lengths and powered costs, and positive costs that underflow to zero, cause errors.

Candidate lists and output use O(nk) storage. After Euclidean search, binary-heap path searches take O(nk^2*log(k+1)) time with O(n+k^2) scratch. Euclidean search may be quadratic in n in high dimensions. Unlike the implicit distance backend, this function does not scan every complete-graph edge for numeric-range validation.

Value

fermat.knn() returns a list with n-by-k matrices index (1-based neighbor indices) and distance (in nondecreasing order), excluding self. create.fermat.sknn.graph() returns a dgraph formed by the union of these directed selections. Its lengths are Fermat distances, not powered direct Euclidean edges. Vertex degrees can exceed k; components are not repaired. Use graph.geodesic.distances() to sum stored lengths, rather than applying fermat.distances() with p > 1 and powering them again.

References

McKenzie, D. and Damelin, S. (2019). Power Weighted Shortest Paths for Clustering Euclidean Data. Section 5, Lemma 5.6 and Algorithm 2. https://arxiv.org/abs/1905.13345.

See Also

Title

Intrinsic Euclidean distances on the nonnegative L-infinity simplex

Name

linf.simplex.distances

Description

Max-normalizes each sample and computes the shortest Euclidean-length path constrained to the union of faces where at least one coordinate is one. This is not Chebyshev distance and does not use a data-derived graph.

Usage 

linf.simplex.distances(
  points,
  sources = NULL,
  targets = NULL,
  pairs = NULL,
  return.paths = FALSE
)

Arguments

points

Numeric matrix with samples in rows and nonnegative abundances in columns. Each row must have a positive maximum. Relative abundances, counts, and max-normalized coordinates give the same answer.

sources, targets

Optional vectors of one-based row indices. Defaults to every row. Repeated indices are allowed.

pairs

Optional two-column integer matrix of one-based row pairs. When supplied, sources and targets must be NULL.

return.paths

Return one shortest piecewise-linear path per requested pair, together with the distances? Intended for small diagnostic queries.

Details

Same-face distances equal Euclidean chords. Different-face paths may visit intermediate faces. The algorithm minimizes an exact unfolding cost over face sequences using Dijkstra’s algorithm. It does not restrict paths to the endpoint faces. Computation uses double precision.

With deficits a = 1 - u and b = 1 - v, a face sequence contributes squared distance sum((u-v)^2) + 2 * C, where C is the sum of a[j] * (b[i] + b[j]) over successive faces i,j. Start faces have a[i]=0; end faces have b[j]=0. A minimum-cost sequence has ordered unfolding crossings and therefore realizes a path on the simplex.

Work per pair is quadratic in the number of features present in either sample, with additional pruning. Matrix output uses sources-by-targets memory. Use pairs or selected sources to avoid a dense all-pairs result.

Value

A sources-by-targets numeric matrix, or a vector for pairs. With return.paths=TRUE, a list with distances and paths; paths are ordered like as.vector(distances). Each path contains points in max-normalized coordinates, one-based face indices, and unfolded-segment times.

Title

Validate a Maximal Packing

Name

validate.maximal.packing

Description

Validates whether a given vertex packing is maximal and correctly satisfies the distance constraints. A packing is valid if all vertices are separated by at least the specified radius, and is maximal if no additional vertices can be added without violating this constraint.

Usage 

validate.maximal.packing(
  adj.list,
  length.list,
  packing.vertices,
  max.packing.radius
)

Arguments

adj.list

A list where each element is a vector of adjacent vertex indices (1-based) for the corresponding vertex.

length.list

A list where each element is a vector of edge weights corresponding to the adjacencies in adj.list.

packing.vertices

An integer vector of vertex indices (1-based) that form the packing to be validated.

max.packing.radius

A numeric value representing the minimum distance that should separate any two vertices in the packing.

Details

This function performs two key validations:

  1. Packing Property: Verifies that all vertices in the packing are separated by at least max.packing.radius.

  2. Maximality: Verifies that no additional vertex can be added to the packing without violating the packing property.

The function uses the igraph package to compute shortest path distances between vertices using Dijkstra’s algorithm.

Value

A list with class "packing_validation" containing validation results:

valid

Logical indicating whether the packing satisfies the distance constraint

min.packing.distance

The minimum distance found between any two packing vertices

max.coverage.distance

The maximum distance from any non-packing vertex to its nearest packing vertex

violations

A data frame containing details of any violations found, or NULL if none. Contains columns: type, vertex1, vertex2, distance

is.maximal

Logical indicating whether the packing is maximal (no vertices can be added)

potential.additions

Integer vector of vertex indices that could potentially be added to the packing if it’s not maximal, or NULL if maximal
