# Profiling contract details

The primary numerical source and algorithms were unchanged. Compilation reused accepted Stage-1 core object files and pinned Rust archive. JSON is confined to the external benchmark driver and saved evidence. R uses the Stage-3 qualified R-devel private library and native module. Its profiling wrapper is a process-local copy of the maintained wrapper with timers around `.Call` and graph construction; no installed source or namespace was changed.

Input parsing is excluded, but representations differ: native starts with typed vectors, R with matrices, and Python with parsed lists that `preprocess` converts to NumPy arrays inside the measured call. This study measures those declared client pipelines. It does not isolate a language effect or claim an exact common conversion boundary. The Python recorder still constructs the accepted observation payloads (including dense kernel conversions) before discarding full payloads in summary mode. Native still constructs typed core events; R keeps its richer solver summaries. The full qualification establishes output preservation, not negligible or identical observation overhead.

Native/Python initialization ends at the `processed` event, pruning ends at `graph_stop`, and final time ends at return after dense affinities are available. Intervals include observer work. Native solver-record time covers LP coefficient construction through acceptance checks; Python solver-record time begins after evaluated LP construction and covers canonicalization, solve and checks. These nested timers are not directly comparable solver-only measurements. R native-bridge time includes conversions and the core; its graph-construction timer includes all three dgraphs objects. The remaining R wrapper time is computed by subtraction with millisecond clock resolution. Component medians need not sum to the median total.

The setup timer starts inside the program and ends before its first call. It includes fixture loading (all three fixtures for native/Python, two for R), Python reference generation and module imports after the timer starts. OS process launch and interpreter initialization before script execution are not separately isolated. End-to-end process wall time includes setup, calls, result serialization and teardown. Worker peak memory includes the same phases, all loaded fixtures and retained allocator capacity. R memory has a different fixture schedule, so no R/native memory ratio is inferred. Workers run serially with one numeric thread on the owner's shared Mac; exclusive host access was not established.

The accepted generic resource guard supervises process-tree RSS, wall time and output limits. Entry reservations bound the potential attempts before each launch. Native/Python also append attempt markers immediately; R only supplies its history on return. An interrupted R call would debit 250 possible attempts rather than invent an exact count. All 23 actual children completed and were reaped. No resource limit or numerical refusal terminated a run. Eight qualification calls, 96 persistent calls (24 warmups and 72 timed repetitions), and six checkpoint calls used 5,166 attempts. The full-payload census recalculates 846 saved optimization certificates; the other 4,320 attempts have exact compact-history and final-output regression checks. Successful normalized retries are part of the unchanged algorithm, not hidden failed process reruns.
