# Phase06A source and reproduction

Canonical API: `include/ian/core.hpp`. The contract is in [SCHEMAS.md](SCHEMAS.md).
`src/core.cpp` implements it and the private test entry points. `src/cli.cpp` and
`src/json_adapter.hpp` own the file-format boundary; `src/r_bridge.cpp` is the
limited direct R adapter. Only the public `ian/core.hpp` header is installed.

The private `numeric.hpp`, `solver.hpp`, `input.hpp`, `stages.hpp`, `engine.hpp`
and file-adapter `checkpoint.hpp`, plus the configuration and two attribution
files, are generated by `extract.py` from immutable Phase04 sources. The generator
is canonical for those files; do not manually edit the generated copies.
`extract.py --check` checks all generated bytes. It retains mathematical code and
ordering and makes explicit substitutions for engine observation and output.
Other phase06a sources and Markdown reports are authored canonical files.

The supported public calling pattern is:

```cpp
#include <ian/core.hpp>
ian::Input input; // Populate features, distances and specimen_ids.
ian::Result result = ian::run(input);
// Check result.complete/error and stage validity before consuming results.
```

Use C++17 with the installed `ian::core` CMake target. The core requires the
pinned native Clarabel library. No Python, R, JSON header or filesystem API is
part of its public header. The implementation still has private JSON and solver
dependencies, and its test-only interface is intentionally not installed.

## Generated evidence

- `regressions-v1`: eight complete CLI runs, twelve probes, two stage suites,
  retained controlled exceptions and pruning-cap case, plus comparisons.
- `clean-v1`, `clean-v2`: source/dependency snapshots, vendored crates, build trees,
  installed prefixes and logs. The second is canonical for feasibility execution.
- `feasibility-v1`: clean CLI run, external consumer results, R checks/RDS/session
  information, exact input transfers and ownership/error checks.
- `analysis-v1`: every available raw-payload check, checkpoint reconstruction,
  solve accounting and derived table. Observer-free calls are separately counted.
- `final-checks-v1.json`, `final-manifest-v1.json`: preservation, extraction,
  compiled-source identities and hashes. The live coordinator roadmap is allowed
  to advance; its Phase05 entry is checked against that historical commit.

`finalize.py` checks the existing accepted input/evidence/source manifests before
freezing the new bundle. The handoff is outside the bundle and written afterward
to name the final commit and manifest hash without a circular dependency.

This is a bounded internal prototype submission. No public release, general ABI,
package portability, crash recovery, resumption, concurrency or performance
improvement is established by these commands.
