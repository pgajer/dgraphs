# IAN implementation and methodological improvement: aims and scope

Version 0.1, consolidated 18 September 2026. Scientific owner: Pawel Gajer.
This working charter records the organization explicitly authorized by the owner.
Its consolidated wording has not received a separate scientific sign-off. It does
not authorize additional experiments, a new numerical policy or deployment.

## Purpose

Establish whether a transparent, reproducible IAN implementation can provide useful
local neighborhoods and affinities at a defensible computational cost, and study
improvements without confusing them with faithful reproduction. The project serves
the approved ZAPPS-PreSSMat scientific aims, especially cohort-specific community
organization and comparisons between cohorts. IAN is a candidate method; its
superiority, a shared biological manifold and meaningful branches are not premises.

## Stable aims

| ID | Question and intended outcome | Evidence needed |
|---|---|---|
| IA1 | Which mathematical formulation, numerical policy and reference behaviors can be faithfully reproduced? | Fixed-problem certificates and complete trajectory comparisons, with historical-expression differences retained. |
| IA2 | Can the calculation operate as a maintainable, reusable and recoverable library with usable interfaces? | Interface contracts, fault/restart tests, complete accounting and declared build/platform qualification. |
| IA3 | What time and memory benefits are attainable under comparable workloads? | Matched persistent pipelines and full-engine measurements, separating startup, solver and other work. |
| IA4 | Which explicitly named numerical or algorithmic changes improve robustness or utility? | Prospective bounded comparisons against frozen controls; rejected changes and negative results count as evidence. |
| IA5 | When are the resulting neighborhoods and affinities useful for declared scientific tasks? | Simulations and appropriate real-data evaluations against simpler alternatives, including known conditional means. |

An investigative aim can be advanced by a well-supported negative result. A
successful build, matching numerical trace or attractive embedding does not establish
biological validity. Agreement in objective values does not imply agreement in
local scales, pruning decisions or scientific conclusions.

## Separate acceptance questions

Mathematical formulation, implementation fidelity, numerical robustness and
scientific usefulness require different evidence. Audit acceptance concerns named
versions and bounded claims. Policy adoption, advancement and production use are
separate investigator decisions. A complete negative study can be accepted while
the scale ladder remains closed. Engine acceptance does not validate downstream
conditional-mean, association or covariance estimators; unresolved downstream issues
also do not block unrelated core engineering.

## Deliverables and boundaries

The intended products are a versioned reference/core and interfaces; numerical and
operational regression collections; reproducible resource measurements; separately
named method alternatives; and qualified scientific applications. Final package
placement and supported platforms remain decisions, not assumptions from the
current repository location. Cohort analyses need population, assay, visit, distance,
transformation, duplicate and participant contracts. Exact profile duplicates are
not interchangeable participant identities.

No full-cohort fit, solver adoption, tie-breaking rule, relaxed tolerance, public
release or new data authorization follows from this charter. Scientific scope
changes require a dated owner decision. Keep this charter stable when updating
results; record evidence in the aim map and synthesis instead.
