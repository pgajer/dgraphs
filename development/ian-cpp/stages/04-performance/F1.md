# Stage-4 F1: exact validation of saved R objects

The independent auditor found that `jsonlite` with `digits=NA` rounds some binary64 numbers in the compact R result JSON. Exact equality of those JSON files establishes equality of rounded projections, not exact equality of the original R objects. The numerical outputs and measured times were not changed or rerun.

The separate read-only checker `check_rds.R` now compares all 24 saved persistent R objects with their full-diagnostic qualification RDS objects. It requires exact equality of complete graph, scale, affinity, mapping, backend and diagnostic structures, including every solver-history field except elapsed seconds. Only the full trace is omitted for the summary-versus-full comparison. It also re-encodes each qualification trace with the existing 17-significant-digit writer and requires exact equality with the saved full trace, verifies all history fields against that trace, and compares each qualification object with an independently accepted Stage-3 RDS object. These qualification-to-reference comparisons exclude seconds only, including full traces and backend identities. The main driver now runs this checker before marking future persistent measurements complete; compact JSON remains a convenient rounded projection.

All 26 objects pass, covering 90 qualification and 1,080 persistent solver-history records. The first read-only check used the earlier Stage-3 PreSSMat package snapshot and stopped on its different source-identity string; all numerical fields agreed. That failed check is preserved. The final check uses the final accepted source identity: the corrected R 4.5.2 PreSSMat object and R-devel helix object. No field was silently excluded to make this comparison pass.
