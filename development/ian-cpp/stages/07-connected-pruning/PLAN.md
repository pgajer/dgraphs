# Connectivity-preserving IAN: implementation contract

23 September 2026. The owner authorizes implementation of the agreed candidate-by-candidate bridge guard with useful R diagnostics. This is IAN-EXP-033, an explicit method variant, not promotion or alteration of the reference numerical policy. Reference pruning remains the default; request the new mode with the dotted R argument `preserve.connectivity=TRUE`. The function remains internal and unexported.

## Pruning semantics

Preserve global volume statistics, retuning, threshold/floor/cap, median-expansion rule and solver certification. Protected edges remain in those calculations. A potential edge proposal is a vertex's longest current incident edge; vertices are visited in descending statistical order, retaining the original ordering convention for median expansion. At each actual proposal, check the permanent bridge cache, then test current bridge status by endpoint reachability with that edge omitted. Only for a nonbridge evaluate the point's pruning eligibility and per-batch endpoint exclusions. A surviving bridge cannot cease being a bridge under edge deletions, so cache it for the run. Never cache a nonbridge conclusion across deletions. No edge addition or vertex removal is allowed.

Global threshold/ranking context is computed from the full graph before scanning; this is not a masked statistic. Per-edge pruning eligibility is evaluated only after its bridge check. The original ten-percent allowance is computed from the original unprotected statistical candidate count, with a minimum of one, but counts actual deletions. Skipped bridges do not consume that allowance. Visit the full remaining proposal order until the deletion allowance is met or the pass ends; do not substitute a shorter incident edge when the longest edge is protected. Keep the reference rule excluding two deletions incident to the same vertex in one batch. A pass with no deletion terminates with a named connectivity-constrained stopping reason, even if statistical candidates remain. This prevents an endless loop with protected candidates.

Require a connected initial graph, otherwise return a structured unsupported-initial-connectivity result before the first solve. Do not silently connect an initial graph. Retain initial and last-valid graphs on refusal/interruption; final graph still requires complete scale/affinity output. Baseline mode follows its existing branch and trace fields unchanged. Connectivity mode and its cache/diagnostics are represented by typed C++ objects and bound to native input/checkpoint identity. Resume must reject mismatched mode or invalid cached bridges and preserve the stopping reason and bridge history. R restart remains outside the interface.

## R diagnostics

Return initial/final/last-valid graphs as before. Add the explicit pruning policy and, for the connected variant, one-based protected edges with stable profile IDs, first/last encounter iteration, encounter count and first statistic/threshold/margin. These are encountered bridge proposals, not a claim that every bridge met the pruning condition. Include per-iteration examined/bridge-skip/condition-rejection/conflict/deletion counts and stopping reason. Full traces additionally record every proposal, bridge outcome and whether pruning eligibility was tested, with the existing declared zero-based trace indexing. Summary diagnostics avoid dense per-attempt payloads. Retain protected edges and iteration diagnostics on failure. Protect native/R ABI compatibility explicitly; an old optional module must produce an actionable rebuild error rather than an arity mismatch.

Check the bridge predicate against component counting, including exhaustive small graphs; the disconnected case must never be reported as newly connected. Preserve the strict/reference full traces on the four established small examples and the nine Stage 5 datasets under their saved policies, plus the accepted 1,000-profile helix native regression. Compare saved/fresh results excluding timing and source identities.

They are not a new comparative scientific benchmark. Independently reconstruct all bridge checks and removals from saved native traces, and validate numerical payloads with the existing full certificate checker. Compare complete native/R results and connected-state history. Reproduce native interruption/resume at pruning and constrained graph boundaries, including cache integrity and mode-mismatch rejection. Test R argument validation, summary/full agreement, duplicate profile mapping and partial-result diagnostics; initial graph and affinity remain distinct objects.

Freshly build the optional module and CLI from a pinned source snapshot on the available Mac arm64 R-devel runtime. Reuse the identified accepted Rust archive without claiming a new Rust/platform build. Install the changed package into a fresh private library; regenerate R documentation from source and run targeted package tests and the appropriate archive/package checks. Do not alter shared installations, export the function, merge or publish. Existing other-platform/R-size limitations remain explicit.

## Bounds and completion

Ceilings: 80 engine entries, 10,000 physical solver attempts, 1,500 per entry, 900 seconds per numerical process and 7,200 aggregate numerical child seconds, sampled 4 GiB process-tree memory, 2 GiB process output and 24 GiB study evidence. Run serially with one numerical thread, reserve before launch, reap every child and retain refusals. Build/package checks have separate command records and time bounds. Data and artifacts go under the dated connected-pruning private directory. Stop on unexplained reference divergence or lost connectivity; do not tune thresholds to rescue a result.

Completion includes a documented R example, reproducible evidence and report, and the same independent auditor's disposition with findings resolved. A connected result alone establishes neither valid biological bridges nor predictive superiority. Outlier deletion, cohort fits, distance-repair methods, public default changes and scientific deployment are outside this implementation.
