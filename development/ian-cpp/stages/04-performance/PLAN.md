## Matched contract and qualification

Each timed call starts with already parsed input and finishes with the initial Gabriel graph, final graph, scales and dense affinities in memory, plus compact solver history. Input validation and duplicate handling are included; file parsing, module imports, compilation and final file serialization are excluded and recorded separately. No durable checkpoint or full diagnostic trace is requested in these primary calls. The native observer and Python recorder retain compact history; the R summary interface retains its documented richer summaries. These are complete implementation pipelines, not isolated language or solver benchmarks: Python includes CVXPY assembly and native builds the evaluated LP directly. R adds validation, native conversion and dgraphs graph construction. Instrumentation and unavoidable diagnostic differences must be disclosed rather than claimed identical.

First run one full-trace qualification per fixture/interface (eight entries), comparing optimization inputs, attempts, decisions and final outputs with accepted evidence. Native and Python use the same driver as timings, with full recording enabled outside the timed interval where possible. R uses the actual summary/full switch. Every later summary result must match its qualified initial/final graph, scales, affinities and compact history; timing fields are excluded. Qualification failures stop dependent measurements and require a prospective amendment.

For each interface, run three fresh worker processes in serial blocks, rotating native/Python/R order. Within each worker run one warmup and three measured repetitions per applicable fixture. Warmups are reported and counted, excluded only from the steady-state summaries. Each worker loads modules once and reuses the process, but allocates a fresh solver for each attempt. Reset Python recorder and parameter registries between entries. This is 96 entries (72 on common fixtures, 24 on the larger quadform); repetitions measure this machine's variability, not independent scientific samples. Report process startup/loading and peak resident memory separately from per-call elapsed time. Peak memory includes libraries, warmup and prior calls; it is a worker high-water mark, not a per-fixture allocation estimate. Use medians and observed ranges, avoiding population confidence claims.

Profile native/Python initialization up to the processed-input event, pruning until graph completion, and final affinity retuning/output. Aggregate existing solver timers, explaining their different code boundaries and treating them as within-interface attribution only. R separately times the native bridge (including conversion and the core), graph construction and remaining wrapper work. Do not label event intervals as pure function costs. Investigate further only when these measurements identify a material bottleneck.

Separately run three native CLI pairs on the 500-profile helix, with full traces and identical output contracts: checkpoint every pruning boundary versus graph-only checkpoint (`--interval 2000`). This six-entry diagnostic measures native checkpoint overhead only. Both variants must reproduce the qualified result. Checkpoint work has no matched Python/R recovery implementation and cannot support a cross-interface claim.

## Limits, recording and review

Planned entries: 110; ceiling 128, at most 20,000 physical solver attempts cumulatively, 250 per entry, 900 seconds per process and 3,600 aggregate numerical child seconds. One numeric thread, serial workers, at most two compiler jobs. Enforce 4 GiB sampled process-tree RSS, 2 GiB per process output, 24 GiB total evidence and at least 20 GiB free. Compilation and read-only validation are recorded separately; no full package rebuild is needed. Persist launch reservations before execution, reap every permitted child before deciding whether another may launch, and preserve failed/interrupted records. Log each engine entry before execution. Native/Python log attempts as they complete. The unchanged R interface returns its attempt history at call completion; an interrupted R call therefore has an unknown exact attempt count and is conservatively charged its full 250-attempt reservation.
