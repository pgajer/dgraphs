# Phase06B source and reproduction

The [plan](PLAN.md), [amendment](AMENDMENT-1.md), [schema](SCHEMA.md) and
[report](REPORT.md) define this bounded implementation and its results.

`extract.py` is canonical for the engine substitutions, unchanged private
numerical/solver/input/stage/checkpoint headers, existing file observer,
configuration and attribution copies from Phase06A. `src/restart_methods.inc`
contains the new engine methods and is included in the compiled source identity.
The public header, core wrapper, JSON state adapter, store and CLI are authored
sources. Other scripts and Markdown documents are authored canonical files.
The Phase06A tree is unchanged. `extract.py --check` verifies generated bytes.

The standard C++ entry points are `ian::run` and `ian::resume`. A caller's observer
may persist the state delivered by `on_checkpoint`; the CLI supplies the tested
filesystem policy. Only accepted pruning/graph boundaries are supported. The
public result remains distinct from its persistence status. Checkpoint hashes
bind source/configuration identities; exact runtime/platform portability is not
claimed. The CMake target and native dependency remain as in Phase06A.

Each driver and subprocess preserves command, working directory, source revision,
exit status and resource samples. The actual schema invocation and first census
were launched before their corrected replacements; source revisions in the logs
identify each harness version. The refused prelaunch before periodic testing is
recorded separately and created no child or solver work. Existing dependency and
linker warnings are retained in build logs. All runtime sources remain byte-
identical to the corrected build at `bab88cc`; later commits add only harnesses,
analysis and documents. No Rust dependency rebuild was needed for this phase.

`regressions-v1` is the original resource-heavy workload, `regressions-v2` the
corrected full workload. `recovery-v1` contains kill handshakes, injected failures,
mutations, continuations and ownership checks. `schema-v2` and `periodic-v1`
contain the successful focused tests. `analysis-v3` contains the final no-solve
census and state/hash reconstruction; prior analyses and errors remain separate.
`final-checks-v1.json` and `manifest-v1.json` preserve source identities, previous
phase/audit bundles and this new evidence. The final handoff is outside the
manifest root to avoid circular hashes. No shared package installation or merge
is part of these commands.
